用 ProxyHints 注册 JDK 动态代理

本课的胜利条件：区分“接口类型可达”和“代理接口组合已注册”，并用最小 JDK proxy hint 修复。

本课已实测完成：接口类型保持可达，先稳定复现代理组合缺失，再注册一个精确 JDK proxy hint，最终 5/5 原生测试通过。

实验场景

应用定义一个代理接口：

public interface ProxyGreeting {
    String format(String name);
}

接口名来自配置，而代理接口数组在运行时才组装：

demo.greeting-proxy-interface=\
com.example.nativedemo.greeting.proxy.ProxyGreeting
Class<?> proxyInterface = Class.forName(interfaceName);

Object proxy = Proxy.newProxyInstance(
    proxyInterface.getClassLoader(),
    new Class<?>[] { proxyInterface },
    invocationHandler);

刻意隔离故障边界

红灯版本已经使用 reflection hint 注册 ProxyGreeting 类型，因此 Class.forName() 不会抢先失败：

hints.reflection().registerType(ProxyGreeting.class);

AOT metadata 中可以看到接口类型，但没有 JDK proxy 组合：

{"type":"com.example.nativedemo.greeting.proxy.ProxyGreeting"}

为什么接口可达仍然不够？

接口类型可达
    ≠
实现该接口组合的代理类已生成

普通 JVM 可以运行时生成新的 $Proxy 字节码。Native Image 运行时不能再补进一个构建时不存在的代理类，因此必须提前知道完整接口列表；多个接口时，接口顺序也属于代理组合的一部分。

检索练习：最准确的根因是哪一个？

最小修复：注册接口组合

在同一个 registrar 中保留两条不同职责的 metadata：

public void registerHints(
        RuntimeHints hints, ClassLoader classLoader) {
    // 允许 Class.forName(interfaceName)
    hints.reflection().registerType(ProxyGreeting.class);

    // 允许 Proxy.newProxyInstance(...) 使用这个接口组合
    hints.proxies().registerJdkProxy(ProxyGreeting.class);
}

Spring AOT 随后生成代理条目：

{
  "type": {
    "proxy": [
      "com.example.nativedemo.greeting.proxy.ProxyGreeting"
    ]
  }
}
接口顺序是注册键的一部分。注册 [A, B] 不等于注册 [B, A]。Hint 的接口顺序必须和运行时传给 Proxy.newProxyInstance() 的数组一致。

代理修复增加了代理实现相关类型和方法，但没有增加资源文件。这再次说明 reflection、resources 和 proxies 是三类独立 metadata。
