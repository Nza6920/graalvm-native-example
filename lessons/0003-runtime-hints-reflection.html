用 RuntimeHints 修复反射可达性

本课的胜利条件：能够解释为什么同一段反射代码在 JVM 正常、Native 失败，并用最小范围的 runtime hint 修复。

本课已实测完成：先稳定复现 ClassNotFoundException，再用精确到构造器和方法的 hint 修复，最终 3/3 原生测试通过。

实验场景

应用没有直接写 new FriendlyGreetingPlugin()，而是从配置读取类名：

demo.greeting-plugin=\
com.example.nativedemo.FriendlyGreetingPlugin

服务在运行时才加载它：

Class<?> pluginType = Class.forName(pluginClassName);
Object plugin = pluginType.getDeclaredConstructor().newInstance();
return (String) pluginType.getMethod("message").invoke(plugin);

先建立 JVM 绿灯

./gradlew test \
  --tests com.example.nativedemo.ReflectiveGreetingTests

结果：BUILD SUCCESSFUL。JVM 的 classpath 中保留了所有应用类，因此运行时可以按字符串寻找该类。

再观察 Native 红灯

./gradlew nativeTest

nativeTest 不支持普通 Test 任务的 --tests 过滤器，因此这里运行完整原生测试套件。

2 tests successful
1 test failed

Caused by: java.lang.ClassNotFoundException:
com.example.nativedemo.FriendlyGreetingPlugin

这次原生测试程序编译耗时 5 分 14 秒，完整 Gradle 任务耗时 5 分 46 秒，峰值 RSS 5.18 GB。失败发生在生成后的原生程序运行阶段，不是 Java 编译阶段，也不是 Native Image 构建阶段。

为什么源码里有类，Native 仍找不到？

Native Image 使用闭世界假设。配置文件里的字符串只有在运行时才变成类名；静态分析没有看到对实现类的直接调用，也没有收到反射提示，因此可以把该类当作不可达代码移除。

JVM:
完整 classpath → 运行时按名称寻找 → 找到

Native:
构建期可达性分析 → 没有静态边 → 移除
                        ↑
                  RuntimeHints 要补的边
检索练习：最准确的根因是哪一个？

最小修复：精确注册调用点

实现 RuntimeHintsRegistrar，注册目标类型、无参构造器和 message()。这里选择 ExecutableMode.INVOKE，因为程序不只是查看成员，还会实际调用它们。

public final class GreetingRuntimeHints
        implements RuntimeHintsRegistrar {

    @Override
    public void registerHints(
            RuntimeHints hints, ClassLoader classLoader) {
        hints.reflection()
            .registerType(FriendlyGreetingPlugin.class, type -> type
                .withConstructor(List.of(), ExecutableMode.INVOKE)
                .withMethod(
                    "message", List.of(), ExecutableMode.INVOKE));
    }
}

然后让 Spring AOT 导入它：

@SpringBootApplication
@ImportRuntimeHints(GreetingRuntimeHints.class)
public class NativeDemoApplication {
    // ...
}
不要习惯性注册所有成员。如果只调用一个构造器和一个方法，就精确注册这两个调用点。范围越宽，越难知道应用真正依赖哪些动态行为，也可能增加镜像元数据。

诊断顺序

JVM 测试失败
  → 先修普通业务或 Spring 配置

JVM 成功，Native Image 构建失败
  → 看构建期可达性或不支持特性

Native Image 构建成功，运行时报 ClassNotFoundException
  → 检查配置驱动加载和 reflection hints
