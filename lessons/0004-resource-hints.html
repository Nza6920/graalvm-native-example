用 ResourceHints 打包动态资源

本课的胜利条件：能够解释为什么资源在 JVM classpath 中存在，Native 运行时却找不到，并用最小资源模式修复。

本课已实测完成：先稳定复现资源缺失，再注册一个精确资源模式，最终 4/4 原生测试通过。

实验场景

资源文件位于：

src/main/resources/greetings/resource-greeting.txt

资源路径不是代码常量，而是来自配置：

demo.greeting-resource=greetings/resource-greeting.txt

服务在运行时按这个路径读取：

ClassLoader classLoader =
    ResourceGreetingService.class.getClassLoader();

try (InputStream input =
        classLoader.getResourceAsStream(resourcePath)) {
    if (input == null) {
        throw new IllegalStateException(
            "Classpath resource not found: " + resourcePath);
    }
    // ...
}

配置可读，不代表所有资源都已打包

服务已经从 application.properties 中取得正确路径，说明应用配置本身存在。缺少的是那个由动态字符串指向的自定义文本文件。

JVM:
完整 classpath → 动态路径 → 找到资源

Native:
构建期资源集合 → 没有模式匹配 → 文件未进镜像
                              ↑
                     ResourceHints 要补的信息
检索练习：最准确的根因是哪一个？

最小修复：注册一个资源模式

在 greeting.resource 模块内部实现 registrar，只注册实际读取的文件：

public final class ResourceGreetingRuntimeHints
        implements RuntimeHintsRegistrar {

    @Override
    public void registerHints(
            RuntimeHints hints, ClassLoader classLoader) {
        hints.resources().registerPattern(
            "greetings/resource-greeting.txt");
    }
}

然后把 hint 的导入也留在这个模块：

@RestController
@ImportRuntimeHints(ResourceGreetingRuntimeHints.class)
class ResourceGreetingController {
    // ...
}

Spring AOT 生成的 reachability metadata 包含：

{"glob":"greetings"}
{"glob":"greetings\/resource-greeting.txt"}
模式不要写得过宽。greetings/** 适合确实要读取整个目录的场景；这里只用一个文件，就注册完整路径。
